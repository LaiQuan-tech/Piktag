# 30 — 派工 prompt 模板(照抄填空)

> 用法:複製對應模板 → 填 {…} → 用 Agent 工具派出。model 建議照
> `10-DISPATCH.md` 第 3 節;拿不準用 sonnet。
> 每個模板已內建三件套(目標動機/驗收/回報)與回報合約,不要刪。

## 通用尾巴(每個模板都以此結尾,已含在各模板內)

```
回報合約:最終訊息只回結論與依據(檔案:行號),不貼整檔。
產物超過 30 行 → 寫進 {輸出路徑},回報只給路徑+3 行摘要。
找不到/做不到 → 明說,並列出已排除的可能,不准編造。
```

## 1. 搜尋/定位(agent type: Explore,model: haiku 或 sonnet)

```
在 {repo 或目錄} 找出 {要找的東西,例:所有寫入 piktag_connections 的呼叫點}。
動機:{為什麼要找,例:要統一成 lib/connectUsers,需要完整清單才不會漏}。
搜索廣度:{medium | very thorough(多目錄多命名慣例時用後者)}。
驗收:每個結果附 檔案:行號 + 一行說明它做什麼;明說你搜了哪些
pattern(讓我能判斷有沒有漏);若結果超過 20 個,按 {分類方式} 分組。
回報:清單即可,不貼程式碼區塊。找不到 → 說明搜過的 pattern 與目錄。
```

## 2. 實作(agent type: general-purpose,model: sonnet;動鎖定契約用 opus)

```
實作:{做什麼,一句話}。
動機:{使用者原話或需求背景,讓你在邊界情況能對齊意圖}。
規格:
- {具體行為 1}
- {具體行為 2}
必守契約(違反即重做):{從 CLAUDE.md 硬規則挑相關的貼進來,
例:i18n key ×19、dark-mode makeStyles 模式、無 emoji}。
驗收(全過才算完成):
- tsc 0 錯(cd {mobile|.} && npx tsc --noEmit)
- {功能級驗證,例:19/19 locale assert 通過}
- 不 commit(由主對話統一 commit)
回報:改了哪些檔(檔案:行號範圍)+ 每檔一句做了什麼 + 驗收逐項結果。
回報合約:(通用尾巴)
```

## 3. 重構(agent type: general-purpose,model: sonnet;並行多份時各加 isolation:"worktree")

```
重構:{目標,例:把 X 的 inline 複本換成 lib/Y 的共用版}。
動機:{例:CLAUDE.md 共用元件鐵律;現況有 N 處複本會 drift}。
範圍:只動 {檔案清單};清單外的檔案發現問題 → 回報,不要動。
行為不變條款:對外行為/輸出必須完全不變;你認為「順手改進」的地方
一律只回報不執行。
驗收:tsc 0 錯;{若有測試:npm test 綠};diff 只含範圍內檔案。
回報:每檔的變更摘要 + 驗收結果 + 你注意到但沒動的問題清單。
回報合約:(通用尾巴)
```

## 4. 研究(agent type: general-purpose,model: sonnet;判斷型結論用 opus)

```
研究問題:{一句話,例:Play Console 商店文案各欄位的字數上限與生效流程}。
動機:{要拿這答案做什麼決定}。
方法要求:優先官方文件/一手來源;每個關鍵結論附來源 URL;
區分「文件明說」vs「你的推斷」,推斷要標註。
驗收:回答 {列出 2-4 個必答子問題};互相矛盾的來源要並列並給判斷。
回報:結論先行(≤10 行),來源清單附後;長筆記寫到
{scratchpad}/research-{主題}.md 給路徑。
回報合約:(通用尾巴)
```

## 5. 審查/驗收(fresh-context,model: opus 或省略;絕不給實作過程)

```
你是驗收者,與實作者無關,職責是找問題不是背書。
待驗產出:{檔案路徑清單 或 git diff 範圍}。
驗收條件(逐項檢查並打勾/打叉,附證據):
- {條件 1,例:CLAUDE.md 路由表裡每個路徑真實存在}
- {條件 2,例:規則之間無互相矛盾}
- {條件 3,例:每個宣稱的 檔案:行號 打開來真的是那回事}
另外主動找:{該類產物的典型缺陷,例:弱模型會誤讀的模糊語句}。
回報:PASS/FAIL 總判 + 逐項結果 + 問題清單(每條附位置與建議修法,
按嚴重度排序)。沒問題就說沒問題,不要硬湊。
回報合約:(通用尾巴)
```

## 6. i18n 批次(實作模板的特化,model: sonnet)

```
在 mobile/src/i18n/locales/ 的全部 19 個 JSON 加入 key {路徑.名稱}。
各語系譯文:{提供 19 條,或要求 agent 翻譯並遵守:無 emoji、
品牌詞 PikTag/Ask/QR 不譯、正式度跟隨該檔既有文風}。
方法(強制):寫 Python 腳本 json round-trip 插入正確區塊 →
assert 19/19 都有新 key → 印出 git diff --stat。
驗收:assert 通過;diff --stat 顯示 19 files changed 且每檔 +1(或預期行數)。
回報:腳本輸出的 assert 行 + diff --stat 原文。
回報合約:(通用尾巴)
```
