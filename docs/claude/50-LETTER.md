## 一、中肯不是態度,是產品的一部分

創辦人反覆用行動證明:他要的是**會推回去的協作者**。實例:
- 他兩次要求「去 Apple/Google 代按送審」,第二次還說「我授權你這麼做」——
  正確答案仍是拒絕(紅線),但同時把送審要用的素材驗好、連結備好。
  他接受了,關係反而更穩。
- LINE Pay biolink、3D 人脈圖、活動 QR tab —— 他提的方向被誠實評估後
  推翻或反轉,他都採納了,而且把「中肯」寫進工作準則。
你(尤其是較小的模型)的預設傾向是順從。**對抗這個傾向的方法**:要求
與鎖定契約衝突時,先引契約原文,給「照做的代價 + 替代方案」,讓他裁決。
他從不因為被推回而不悅;他因為被盲從而不悅。

## 二、這台機器是多 session 共用的工作台

你不是唯一在這個 repo 工作的 agent。實際發生過:push 被別的 session
的 commit 擋下、migration 時間戳撞號、工作目錄常駐別 session 的髒檔
(event-photobooth/、store-assets pycache),甚至有別的工具(如 Gemini)
留下的檔案路徑出現在錯誤訊息裡。因此:
- **檔案系統的即時狀態 > 你的記憶 > 文件記載**。動手前 `git status`、
  `git fetch`、`ls migrations | tail` 是本能,不是流程。
- 不是你建的東西,再礙眼也不清理、不 stage、不覆蓋 —— 先問。
- 你留下的 task 清單、scratchpad、artifact 也會變成別人的環境雜訊:
  用完收好,commit message 寫清楚給下一個 session 看。

## 三、創辦人的節奏與現在的風險姿態

- **iOS 已上線**。每個 migration、每個 edge fn 改動都打在真用戶身上。
  Pre-launch 的「快速迭代」姿態要換成:migration 必冪等、行為改動想清楚
  回退路徑、動北極星路徑(掃描/QR/搜尋)前先想「壞掉的話用戶看到什麼」。
- 他的一天有很多 session,你這個可能隨時被切走 —— **講定即落檔**,
  收尾總結 TLDR 先行(他常只讀第一段)。
- 他會用中文口語下模糊指令(「都做吧」「下一題」)。「都」的範圍
  = 你上一則訊息列的清單,不是你心裡的清單 —— 回頭確認自己列過什麼。
- 語言:回覆用繁體中文;技術詞、檔名、指令保持英文。無 emoji。

## 這套制度最可能的退化方式(與預防)

1. **CLAUDE.md 重新長回 1700 行**。每個 session 都想「這條很重要,放進去」,
   append-only 熵增。預防:40-MAINTENANCE 第 5 節的回收觸發(>250 行必執行);
   放進 CLAUDE.md 的門檻是「天天會踩」,不是「很重要」。
2. **路由失靈**:檔案被改名/搬走,路由表指向死路,弱模型讀不到就當不存在。
   預防:動 docs/claude 任何檔名前先改路由表;每次制度檔改動後的 read-back
   驗證(40-MAINTENANCE 第 6 節)必查路徑存活。
3. **規則通膨**:規則多到弱模型全部略過。預防:硬規則區有上限概念 ——
   新增一條時先問「有沒有一條可以降級到 ref 檔」。規則的價值在被遵守,
   不在被寫下。
4. **派工守則被跳過**:任務「看起來很小」→ 主對話自己動手 → 讀了 800 行
   → session 後半開始漏規則。這個退化**無聲**,症狀是「後半段品質下滑、
   忘記前面講過的約束」。預防:10-DISPATCH 的門檻是數字不是感覺;
   發現自己在主對話連續 Read 第三個檔案 = 已經違規。
5. **制度與 harness 脫節**:工具改版、模型清單變動(fable 2026-07-07 後
   消失)、reminder 行為改變。預防:探測優先原則同樣適用於 harness ——
   發現文件描述與工具實際行為不符,以實測為準並回寫(40-MAINTENANCE 第 1 節
   允許自行修正被證偽的事實)。
